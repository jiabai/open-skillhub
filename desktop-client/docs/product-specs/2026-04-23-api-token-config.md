# API Token 配置界面

> 状态：产品规格文档

## 这个功能是什么？

让用户在桌面应用内直接配置 API Token 和服务器地址，不再需要用命令行设置环境变量。

简单来说：**打开应用 → 输入 Token → 开始使用**。

## 为什么需要这个功能？

**之前的痛点**

| 问题 | 影响 |
|------|------|
| Token 只能通过环境变量设置 | 普通用户不会操作 |
| 不知道 Token 是否保存成功 | 用户心里没底 |
| 切换服务器地址困难 | 开发/生产环境切换麻烦 |

**目标用户**

- 从管理员那里拿到了 API Token 的操作员
- 需要更换 Token 或切换服务器地址的用户
- 在开发和生产环境之间切换的用户

## 用户怎么用？

### 第一次打开应用

```
1. 应用启动，发现没有 Token
2. 显示配置面板
3. 用户输入：
   - 服务器地址（默认 http://127.0.0.1:8001）
   - API Token
4. 点击「保存」
5. Token 存入系统安全存储（Windows Credential Manager / macOS Keychain）
6. 可选：点击「测试连接」验证配置
7. 进入主界面，开始同步技能
```

### 以后打开应用

```
1. 应用启动，发现已有 Token
2. 直接进入主界面
3. Settings 面板显示当前配置状态
4. 可随时点击「编辑配置」修改
```

### 状态提示

| 状态 | 界面显示 |
|------|---------|
| 未配置 | 显示配置面板，「保存」按钮高亮 |
| 已保存 | 绿色提示：Token 已保存 |
| 连接失败 | 黄色警告 + 具体错误信息 |
| 测试成功 | 连接成功，服务器可用 |
| Token 来自环境变量 | 提示：Token 已从环境变量导入 |

## 安全设计

### Token 怎么存储？

| 内容 | 存储位置 | 原因 |
|------|---------|------|
| API Token | 系统凭证存储（keytar） | 安全敏感，需要加密 |
| 服务器地址 | 本地配置文件 | 非敏感，普通配置 |

**各平台存储位置**

- Windows → Credential Manager
- macOS → Keychain
- Linux → Secret Service

### 安全规则

1. **Token 不回传**：保存后，界面永远看不到实际 Token 值
2. **最小权限**：前端界面只能通过 IPC 调用主进程，不能直接访问文件系统
3. **清除彻底**：清除 Token 时，同时清除服务器地址配置

## 配置优先级

当多种配置来源同时存在时，按以下顺序使用：

**API Token**

```
1. 系统凭证存储（keytar）  ← 最高优先级，用户手动保存的
2. 环境变量               ← 次优先级，首次使用后自动保存到 keytar
3. 未配置                 ← 显示配置面板
```

**服务器地址**

```
1. 本地配置文件（config/config.json）  ← 用户手动保存的
2. 环境变量                            ← 开发者调试用
3. 默认值 http://127.0.0.1:8001        ← 本地开发服务器
```

## 交互规则

### 保存行为

- 点击「保存」后立即保存，不强制要求连接测试成功
- 保存成功后，自动尝试刷新同步状态
- 如果刷新失败，保留配置，显示可操作的错误信息

### 连接测试

- 使用真实的 Client API 测试：`GET /api/v1/client/skills?limit=1`
- 不新增专用健康检查端点
- 测试可选，允许离线配置（服务器可能还没启动）

### Token 来源显示

如果 Token 是从环境变量导入的，界面应显示提示：「Token 已从环境变量导入」

## 成功标准

用户能做到这些就算成功：

1. ✅ 打开应用就能配置 Token，不需要开终端
2. ✅ Token 存在系统安全存储，重启应用不丢失
3. ✅ 保存后能看到明确的成功/失败提示
4. ✅ Settings 面板正确显示当前配置状态
5. ✅ 保存或清除配置后，应用立即生效，不需要重启

## 不做什么

这些功能不在本次范围内：

- 登录界面（用户名 + 密码）
- OAuth 第三方登录
- Token 自动生成
- 多账户切换
