## 核心流程

### 1. Skill 上传流程（含环境创建和依赖安装）

> **前置说明**：Skill UUID 在上传请求开始时即已分配，用于后续所有操作的标识。

```
┌─────────────────────────────────────────────────────────────────────┐
│                        Skill Upload Flow                             │
└─────────────────────────────────────────────────────────────────────┘

用户上传 Skill ZIP
       │
       ▼
  ┌─────────────────┐
  │ 1. 验证 ZIP 文件 │
  │    - 格式校验    │
  │    - 大小限制    │
  │    - SKILL.md   │
  └────────┬────────┘
           │
           ▼
  ┌─────────────────────────────────────────────────┐
  │ 2. 脚本安全扫描                                  │
  │    - 扫描 scripts/*.py 文件                      │
  │    - 检测风险模式                                │
  └────────┬────────────────────────────────────────┘
           │
           ├───────── 检测到 HIGH 级别风险 ─────────▶ 返回安全拒绝错误
           │
           ├───────── 检测到 MEDIUM 级别风险 ────────▶ 返回安全审查确认
           │                                           等待用户决策
           │
           │                                           ⏱️ 超时机制：
           │                                           - 等待时间上限：5分钟
           │                                           - 超时后自动取消上传
           │                                           - 注意：此时尚未加锁，无需解锁
           │

  ┌─────────────────────────────────────────────────┐
  │ 3. 加锁运行时环境                                │
  │    - 检查 runtime_locked 状态                    │
  │    - 若已锁定 → 返回 RUNTIME_LOCKED 错误         │
  │    - 设置 runtime_locked = True                 │
  │    - 设置 runtime_lock_reason = 当前阶段        │
  │      （后续步骤会根据阶段更新）                   │
  │    - 设置 runtime_locked_at                     │
  └────────┬────────────────────────────────────────┘
           │ 成功加锁
           ▼
  ┌─────────────────┐
  │ 4. 解析依赖声明  │
  │    - frontmatter│
  │    - metadata   │
  │    - requirements.txt │
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐     否      ┌─────────────────────────────────────────────┐
  │ 5. 检查用户环境  │───────────▶│ 6. 创建虚拟环境                              │
  │    是否存在？    │             │    - venv 创建                               │
  └────────┬────────┘             │    - 记录路径                                │
           │ 是                    │    - 设置 venv_created_at = 当前时间         │
           │                       │    - 设置 venv_last_used_at = 当前时间       │
           ▼                       │    - 设置 skill_storage_path                │
  ┌─────────────────────────────────────────────────┐     │
  │ 7. 环境已存在时更新使用时间                      │     │
  │    - 更新 venv_last_used_at 为当前时间           │     │
  │    - 表示环境正在被使用，避免被空闲清理误判        │     │
  │    - ⚠️ 注意：新创建的环境已在步骤6设置，此步骤不执行 │     │
  └────────┬────────────────────────────────────────┘     │
           │                                             │
           │                                             │
           ▼                                             ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │ 8. 解析 SKILL.md metadata                                        │
  │    - 提取 script_entry 配置                     │
  │    - 设置 skill.script_file 字段                │
  │    - 默认值为 main.py                           │
  └────────┬────────────────────────────────────────┘
           │
           ▼
  ┌─────────────────────────────────────────────────┐
  │ 9. 依赖冲突检测                                  │
  │    - 对比已安装依赖与新依赖                       │
  │    - 检测版本冲突                                │
  └────────┬────────────────────────────────────────┘
           │
           ▼
  ┌─────────────────┐     有冲突    ┌─────────────────────────────────────────┐
  │ 是否存在冲突？   │─────────────▶│ 10a. 返回冲突信息                         │
  └────────┬────────┘              │    设置 lock_reason =                    │
           │ 无冲突                 │    "Waiting for conflict resolution"     │
           │                        │    等待用户决策（保持锁定状态）           │
           │                        │                                          │
           │                        │    ⏱️ 超时机制：                          │
           │                        │    - 等待时间上限：5分钟                  │
           │                        │    - 超时后自动取消上传并解锁             │
           │                        │    - 防止长时间占用锁阻塞其他操作         │
           │                        └────────┬────────────────────────────────┘
           │                                 │
           │                     ┌───────────┴───────────┐
           │                     │                       │
           │               用户选择              超时自动取消
           │              "允许安装"            （或用户选择"取消"）
           │                     │                       │
           │                     ▼                       ▼
           │            ┌─────────────────┐   ┌─────────────────┐
           │            │ 10b. 卸载冲突包  │   │ 解锁并返回错误   │
           │            │    安装新版本    │   │ 流程结束         │
           │            │    设置 lock_    │   └─────────────────┘
           │            │    reason =      │
           │            │    "Installing   │
           │            │    dependencies" │
           │            └────────┬────────┘
           │                     │
           ▼                     │
  ┌─────────────────────────────────────────────────┐
  │ 10c. 无冲突时返回依赖预览                        │     │
  │     - 设置 lock_reason =                        │     │
  │       "Waiting for dependency preview           │     │
  │        confirmation"                            │     │
  │     - 返回 dependency_preview 状态              │     │
  │     - 展示待安装和已安装依赖列表                 │     │
  │     - 等待用户确认（保持锁定状态）               │     │
  │                                                  │     │
  │     ⏱️ 超时机制：                                │     │
  │     - 等待时间上限：5分钟                        │     │
  │     - 超时后自动取消上传并解锁                   │     │
  └────────┬────────────────────────────┬───────────┘
           │                            │
           │                  ┌─────────┴─────────┐
           │                  │                   │
           │            用户确认安装        超时自动取消
           │           "确认并安装"        （或用户选择"取消"）
           │                  │                   │
           │                  ▼                   ▼
           │         ┌─────────────────┐  ┌─────────────────┐
           │         │ 10d. 更新锁原因  │  │ 解锁并返回错误   │
           │         │    设置 lock_    │  │ 流程结束         │
           │         │    reason =      │  └─────────────────┘
           │         │    "Installing   │
           │         │    dependencies" │
           │         └────────┬────────┘
           │                  │
           ▼                  ▼
  ┌─────────────────────────────────────────────────┐
  │ 11. 安装新依赖                                   │
  │    - pip install [packages]                     │
  │    - 更新 installed_dependencies                │
  │    - 更新 venv_last_used_at                     │
  └────────┬────────────────────────────────────────┘
           │
           ▼
  ┌─────────────────┐     失败     ┌─────────────────────────────────────────────────┐
  │ 12. 安装是否成功？ │────────────▶│ 13. 回滚上传并解锁                              │
  └────────┬────────┘              │    - 回滚依赖状态                               │
           │ 成功                   │    - 删除临时文件                               │
           │                        │    - 删除临时 Skill 目录                        │
           │                        │    - 释放运行时锁（最后执行）                    │
           │                        │    - 返回错误信息                               │
           │                        └─────────────────────────────────────────────────┘
           ▼
  ┌─────────────────────────────────────────────────┐
  │ 14. 创建 Skill 版本                              │
  │     - 写入版本目录                               │
  │     - 创建版本记录                               │
  │     - 设置 skill.script_file（从 metadata）      │
  │     - 注意：版本创建在解锁之前，确保原子性        │
  │       若创建失败，依赖也会回滚                   │
  └────────┬────────────────────────────────────────┘
           │
           ├───────── 创建失败 ─────────▶ 进入步骤 13 的回滚流程
           │
           ▼ 创建成功
  ┌─────────────────────────────────────────────────┐
  │ 15. 解锁运行时环境                               │
  │     - runtime_locked = False                    │
  │     - 清空 lock_reason 和 locked_at             │
  └────────┬────────────────────────────────────────┘
           │
           ▼
  ┌─────────────────────────────────────────────────┐
  │ 16. 返回成功响应                                 │
  │     - Skill 名称、版本                           │
  │     - 已安装依赖数量                             │
  └─────────────────────────────────────────────────┘

说明：
- 版本创建在解锁之前执行，保证原子性
- 若版本创建失败，整个流程回滚（包括依赖）
- 只有所有步骤成功后才解锁，避免部分成功导致状态不一致
- 环境已存在时更新 venv_last_used_at，避免用户删除 Skill 后重传被误判为空闲
- skill_storage_path 首次上传时设置，确保账户删除时级联清理可用
- 超时机制仅适用于等待用户确认场景，安装过程不受此限制
- **lock_reason 状态流转**：
  - 步骤3加锁时初始设置为当前操作阶段
  - 步骤10a冲突等待：`Waiting for conflict resolution`
  - 步骤10c依赖预览等待：`Waiting for dependency preview confirmation`
  - 步骤10b/10d开始安装时：更新为 `Installing dependencies`
- **无冲突时也需要用户确认**：步骤10c返回依赖预览，用户确认后才安装
```

       │
       ▼
  ┌─────────────────┐
  │ 1. 执行 Skill    │

  │    (如上)        │

  │ 剩余 Skill 数量  │─────────────▶│ 正常返回，流程结束│
  │    > 0？        │              │                  │
  └────────┬────────┘              └─────────────────┘
           │ 无剩余（最后一个）
           ▼
  ┌─────────────────────────────────────────────────┐
  │ 3. 环境保留策略                                  │
  │    - 虚拟环境不删除                              │

- venv_last_used_at 保持不变，反映最后一次实际使用时间
- 空闲清理策略：当用户无剩余 Skill AND 空闲天数超过阈值时清理
- 用户可通过管理接口手动清理环境

### 6. Skill 版本回滚流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                     Skill Version Rollback Flow                       │
└─────────────────────────────────────────────────────────────────────┘

用户回滚 Skill 到旧版本
       │
       ▼
  ┌─────────────────┐
  │ 1. 权限验证      │
  │    - 用户认证    │
  │    - Skill 所有权│
  │    - 目标版本存在│
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐     已锁定     ┌─────────────────┐
  │ 2. 检查运行时锁  │─────────────▶│ 返回错误：       │
  │    runtime_locked│              │ RUNTIME_LOCKED   │
  └────────┬────────┘              └─────────────────┘
           │ 未锁定
           ▼
  ┌─────────────────┐     不存在    ┌─────────────────┐
  │ 3. 检查用户环境  │─────────────▶│ 返回错误：       │
  │    是否存在？    │              │ RUNTIME_NOT_INITIALIZED │
  └────────┬────────┘              └─────────────────┘
           │ 存在
           ▼
  ┌─────────────────┐
  │ 4. 获取目标版本  │
  │    - 解析版本号  │
  │    - 定位文件    │
  └────────┬────────┘
           │
           ▼
  ┌─────────────────────────────────────────────────┐
  │ 5. 依赖处理策略                                  │
  │    - 不回滚依赖                                  │
  │    - 不卸载当前依赖                              │
  │    - 不安装旧版本依赖                            │
  │    - 直接使用当前环境                            │
  └────────┬────────────────────────────────────────┘
           │
           ▼
  ┌─────────────────────────────────────────────────┐
  │ 6. 检查依赖兼容性（强制）                          │
  │    - 对比旧版本依赖声明与当前已安装依赖            │
  │    - 检测潜在兼容性问题                            │
  └────────┬────────────────────────────────────────┘
           │
           ├───────── 存在不兼容依赖 ─────────▶ 返回 compatibility_warning
           │                                     调用 POST /rollback/confirm
           │                                     用户确认后继续
           │                                     或取消回滚
           │
           ▼ 依赖兼容或用户确认继续
  ┌─────────────────────────────────────────────────┐
  │ 7. 更新版本指针                                  │
  │    - 设置 current_version = 目标版本            │
  │    - 更新 venv_last_used_at                     │
  └────────┬────────────────────────────────────────┘
           │
           ▼
  ┌─────────────────┐
  │ 8. 返回成功响应  │
  │    - 新版本号    │
  │    - 回滚时间    │
  └─────────────────┘

说明：
- 版本回滚只切换代码版本，依赖保持不变
- 版本回滚需要检查运行时锁，避免与依赖安装操作冲突
- 当前环境的依赖可能已满足旧版本需求
- 避免不必要的依赖卸载/重装，减少操作风险
- 若旧版本依赖与当前不兼容，**提供警告信息**，让用户知晓潜在风险
- 依赖兼容性检查仅用于提示，不强制阻止回滚，用户确认后可继续
- API定义详见 [API 设计 - 版本回滚接口](./06-api-design.md#2-版本回滚接口)
```
