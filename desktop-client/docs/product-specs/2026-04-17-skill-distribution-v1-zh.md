# 桌面客户端技能分发 V1

状态：本地规范产品文档

## 目标

构建一个 Windows 桌面客户端，检测来自 SkillDrive 的新技能或更新技能，暂存待审核，并将批准版本分发到支持的本地代理安装目录。

## 目标

- 提供独立的 Electron 桌面客户端与 React 渲染器
- 检测当前令牌所有者可用的远程技能更新
- 保持更新处于待审核状态，直到操作员明确批准分发
- 一次批准将选定版本分发到所有已启用的支持代理
- 保留足够的本地状态以在重启后恢复待审核更新和同步上下文

## 非目标

- 应用内技能编辑、上传、激活或服务器端管理流程
- 静默自动分发
- 单技能路由规则或工作区特定的分发策略
- 实时推送同步作为 V1 要求

## 支持的代理

- Codex
- Claude Code
- Gemini CLI

## 核心产品规则

- 服务器是技能可见性和版本的权威来源。
- 桌面客户端是本地同步和分发运行时。
- 在操作员明确批准之前，不向任何代理目录写入任何包。
- 分发对已启用的代理是全局的；单代理路由延后处理。
- 不支持的加密下载默认失败。

## 技能审核机制

### 审核定义

技能审核是指**人工审查和批准**从 SkillDrive 服务器检测到的技能更新，然后才能将其分发到本地代理（Codex、Claude Code、Gemini CLI）的安装目录。

### 审核原因

**安全控制**
- 在操作员明确批准之前，不向任何代理目录写入任何包
- 防止未经审查的代码自动进入开发环境

**版本管理**
- 待审核更新面板显示：技能名称、ID、本地版本、远程版本、审核原因
- 让用户清楚知道即将更新什么，避免意外覆盖或破坏现有配置

**防止静默自动化风险**
- 文档明确将"静默自动分发"列为非目标
- 核心信念：没有技能在未经用户明确批准前会被写入代理目录

**审计追踪**
- 活动面板记录所有分发操作和时间戳
- 提供操作历史，便于追踪和回溯

### 审核流程

```
服务器发现更新 → 下载到本地暂存 → 显示在待审核面板 → 用户点击「分发」按钮 → 写入代理目录
```

这是一个**人工审批门控**机制，确保用户对进入开发环境的每个技能更新都有完全的控制权和可见性。

## 技能检测机制

### 检测方式

客户端采用**后台轮询（Polling）**机制自动检测 SkillDrive 服务器上的技能更新。

### 工作原理

**轮询编排**
- Electron 主进程负责后台轮询编排
- 定期调用 `GET /api/v1/client/skills` API 获取远程技能状态
- 同步核心比较远程状态与本地 SQLite 快照记录
- 发现新技能或版本差异后，将更新暂存到待审核状态

**拉取式架构**
- 客户端主动询问服务器是否有更新（Pull 模式）
- 非服务器主动推送通知（Push 模式）
- "实时推送同步"被列为 V1 的非目标

### 检测流程

```
定时器触发 → 调用远程 API → 比较本地快照 → 发现新/更新技能 → 添加到待审核列表 → 通知用户
```

### 关键规则

**轮询限制**
- 轮询仅刷新审核状态并显示待审核更新
- **轮询绝不能自动分发技能**
- 分发必须是操作员的明确操作

**可配置性**
- 轮询间隔可在设置面板中配置
- 默认轮询间隔为 30 秒（30000 毫秒）
- 用户可根据需要调整检测频率
- 可通过环境变量 `SKILLDRIVE_POLL_INTERVAL_MS` 配置

**状态持久化**
- 待审核更新在应用重启后保留
- 本地同步快照使用 SQLite 存储
- 最后刷新时间戳显示在概览面板

## 预期用户体验

- 应用作为 Windows 桌面工具运行，带有托盘图标。
- 后台轮询发现可审核的更新。
- 待审核更新在主窗口中保持可见，直到被处理。
- 一次批准将选定版本分发到所有已启用的支持代理。
- 活动和失败应足够清晰，便于手动重试。

## 分发警告提示

### 批准分发时的用户确认

在用户点击「分发」按钮批准技能同步时，必须显示明确的警告提示：

**警告内容**
- 同步操作将会**覆盖本地所有已安装的 SKILL**
- 同步后，本地技能将与云端版本**完全一致**
- 用户**手动安装的技能不会自动同步到云端**
- 手动安装的技能在同步后**可能会被自动删除**
- 提示用户**谨慎操作**，确认是否继续

**设计意图**
- 防止用户意外丢失本地自定义技能
- 明确告知同步的破坏性后果
- 确保用户在充分知情的情况下做出决定

## 当前已实现的功能

### 核心运行时
- Electron 主进程：托盘行为、轮询编排、通知、分发
- 客户端 API 使用：`GET /api/v1/client/skills` 和 `POST /api/v1/client/skills/download`
- 本地 SQLite 支持的同步快照：待审核更新和已分发技能记录
- 代理适配器：Codex、Claude Code、Gemini CLI

### 渲染器 UI 面板
桌面客户端提供五个核心 UI 面板供操作员交互：

**概览面板 (Overview Panel)**
- 显示审核快照指标：待审核更新数量、本地记录数量、最后刷新时间戳
- 桥接通信失败时显示加载状态和错误消息
- 提供当前同步状态的即时概览

**待审核更新面板 (Pending Updates Panel)**
- 技能审核和分发批准的主要界面
- 列出每个待审核更新：技能名称、ID、本地版本、远程版本、审核原因
- 每项提供「分发」按钮用于明确批准操作
- 分发操作期间显示忙碌状态
- 空状态表示无待审核更新

**代理面板 (Agents Panel)**
- 显示支持的分发目标：Claude Code、Codex、Gemini CLI
- 静态信息面板，显示适配器层就绪状态
- 无交互控件；反映已配置的代理支持

**设置面板 (Settings Panel)**
- 记录审核策略：待审核更新在人工审核前保持锁定
- 显示桥接访问状态（仅 IPC 包装器，无直接 Node 访问）
- 显示存储快照行为（分发前后刷新状态）
- 桥接状态指示器及最后刷新时间戳

**活动面板 (Activity Panel)**
- 显示最近操作历史及时间戳
- 条目类型：neutral（信息）、success（完成）、warning（问题）
- 提供分发操作和同步事件的审计追踪
- 无最近操作时显示空状态

## 当前实现差距

- 尚无规范的包脚本用于在开发中启动完整 Electron 运行时。
- `src/core/storage/secret-store.ts` 已存在，但运行时启动仍从环境读取 `SKILLDRIVE_API_TOKEN`。
- SQLite 状态存储尚未持久化完整的分发历史或备份元数据。
- 更广泛的头脑风暴设计假设比当前实现提供更丰富的可恢复性。

## 架构边界

- 渲染器 UI 仅渲染状态并调用操作。
- Preload 和 IPC 是渲染器到运行时的唯一桥梁。
- Electron 主进程负责轮询、通知、文件系统写入、下载和运行时启动。
- 同步核心比较远程状态与本地记录。
- 分发核心验证包并协调安装。
- 代理适配器负责目标特定的安装和验证行为。

## 安全要求

- 令牌绝不进入明文配置或渲染器状态。
- 包验证在写入代理目录前进行。
- 路径验证拒绝不安全或模糊的技能标识符和目标路径。
- 不支持的加密包在解密边界存在前默认失败。

## 持久化要求

- 待审核更新和本地已分发技能记录在重启后保留。
- 如果 V1 声称重启安全的活动历史，状态存储必须扩展以显式持久化。
- 产品文案不得承诺持久化的分发历史，除非它在 schema 中存在。
