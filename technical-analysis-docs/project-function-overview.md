# Open SkillHub 项目功能说明

## 1. 项目是做什么的

Open SkillHub 是一个面向 AI Agent / MCP 客户端的私有化 Skill 管理与分发平台。它解决的核心问题，不是“在线运行一个 AI Skill 市场”，而是把企业或个人自己的 Skills 集中管理起来，提供上传、版本化、权限控制、下载分发，以及受控执行能力。

从当前仓库实现看，它的产品定位可以概括为：

- 一个带 Web 控制台的 Skill 资产管理平台
- 一个给 AI 客户端使用的 REST / MCP 接入层
- 一个支持多用户隔离、Token 鉴权、审计留痕的私有 Skill Hub

项目主链路是：

1. 用户在 Web 控制台创建或上传 Skill
2. 平台解析 `SKILL.md` 和版本信息，保存 Skill 元数据与文件
3. 用户通过控制台管理启停、版本、可见性、引用和克隆
4. AI 客户端通过 JWT 或 API Token 拉取可访问的 Skill
5. 客户端在本地执行 Skill，或通过 MCP / 工具接口触发受控执行

## 2. 核心功能

### 2.1 用户与认证

项目具备完整的账户体系，支持：

- 邮箱验证码注册与登录
- JWT 访问令牌与刷新令牌
- API Token 创建、展示一次、撤销、过期管理
- 可选 SSO 登录
- 可选 LDAP 登录

这意味着平台同时服务两类访问方式：

- 浏览器用户：进入控制台做管理
- 客户端程序：携带 Token 拉取或调用 Skill

### 2.2 Skill 生命周期管理

这是项目最核心的能力。当前实现支持：

- 创建 Skill 记录
- 上传 ZIP 技能包
- 上传单个文件到已有 Skill
- 解析 `SKILL.md` 前置元数据
- 管理 Skill 描述、名称、标签、可见性
- 启用 / 停用 Skill
- 删除 Skill，并可选择删除归档

Skill 不只是“一个文件夹”，而是带元数据、版本、状态和访问控制的业务对象。

### 2.3 版本管理

项目支持按版本保存 Skill 内容，并围绕版本提供操作能力：

- 当前生效版本管理
- 版本列表查看
- 按版本读取文件
- 下载指定版本或当前版本
- 版本回滚
- 版本差异与安装说明相关接口
- 自动递增版本策略

这说明 Open SkillHub 不只是“上传后覆盖”，而是一个真正有版本轨迹的 Skill 仓库。

### 2.4 公共 Skill、引用与克隆

仓库里实现了公共 Skill 工作流，尤其适合“复用模板，再决定是否私有化维护”的场景：

- 浏览公共 Skill 列表
- 查看公共 Skill 详情
- 将公共 Skill 添加为 reference
- 将公共 Skill clone 成自己的私有副本
- reference 支持 pin 到指定版本或取消 pin

三类 Skill 在当前产品中有明确区分：

- `public`：公共来源，作为可复用源头
- `reference`：引用公共 Skill，本地只保留引用关系，文件只读
- `clone`：从公共 Skill 派生出的私有副本，可继续独立演进

这套设计的价值在于，平台同时支持“共享复用”和“私有分叉”。

### 2.5 Skill 下载与客户端分发

平台提供专门的下载接口给客户端使用，而不是要求客户端直接读存储目录。当前实现支持：

- 按 Skill ID 和版本下载
- 下载权限校验
- 下载速率限制
- 下载体积限制
- 可选下载加密
- 缓存策略返回

这部分能力说明它本质上是一个 Skill Distribution Service。

### 2.6 MCP / 工具执行能力

项目不只是做存储与下载，还保留了 MCP / 工具执行能力。当前代码中可以看到：

- HTTP MCP app 入口
- SSE / HTTP 传输模式支持
- `execute_skill` 工具
- `load_skill`、`read_reference_file`、资源类操作

其中 `execute_skill` 的行为不是任意执行命令，而是受约束的：

- 必须先鉴权并绑定用户上下文
- 必须校验 Skill 是否可见、可执行、已启用
- 公共 Skill 不能直接执行，必须先 reference 或 clone
- 只允许本地脚本型命令
- 支持并发限制、配额限制、超时控制
- 执行结果会进入审计与指标统计

因此，这个平台不仅是“Skill 仓库”，也是“受控 Skill Runtime Gateway”。

### 2.7 权限、组织和可见性

项目实现了企业场景需要的治理能力，且大量能力通过开关控制：

- RBAC 权限控制
- 企业 / 团队 / 个人三级可见性
- 企业、团队、用户身份字段
- 管理端权限校验
- 下载、执行、管理等权限点分离

可见性层级主要包括：

- `private`
- `team`
- `enterprise`

在关闭 RBAC 时，系统更偏个人工作区模式；在开启 RBAC 时，系统更偏组织治理模式。

### 2.8 审计与运维治理

当前实现覆盖了较完整的审计能力：

- 认证相关事件审计
- Skill 创建、上传、下载、激活、停用、更新、删除、回滚、执行审计
- Token 创建与撤销审计
- 用户身份修改和删除审计
- 审计日志筛选与导出

前端也已有审计日志页面，可按时间、操作类型、操作者等条件筛选，并导出 JSON / CSV。

### 2.9 用户管理与后台治理

在管理模式下，平台提供用户管理能力：

- 用户列表查询
- 按用户名或邮箱搜索
- 修改用户身份信息
- 调整企业、团队、角色、状态

这表明它不只是面向单人本地使用，也支持内部平台化管理。

### 2.10 Dashboard 与运营指标

项目提供 Dashboard 概览能力，当前能看到：

- 当前用户可用 Skill 数
- 可用 Token 数
- 最近 24 小时请求成功率
- 指标清理与重置接口

这类能力偏平台运营与健康度观察。

## 3. 前端控制台能做什么

前端是一个 Next.js 控制台，当前页面已经覆盖主要业务流程：

- 首页 / 入口页
- Dashboard 概览
- 登录、注册、SSO、LDAP 登录页
- My Skills / Skills 列表页
- Skill 详情页
- 新建 / 上传 Skill 页
- Public Skills 页面
- Tokens 页面
- Audit 页面
- Admin Users 页面
- Profile / Security 页面

从这些页面设计可以看出，产品主要面向“管理和分发”，不是面向最终消费者的展示型站点。

## 4. 后端提供哪些服务

后端是一个 FastAPI 服务，当前 API 模块主要包括：

- `auth`：注册、登录、刷新、SSO、LDAP、登出
- `skills`：Skill 列表、详情、创建、更新、上传、下载、激活、停用、删除、公共 Skill、引用、克隆、版本相关
- `tokens`：Token 创建、查询、撤销
- `audit`：审计日志查询与导出
- `dashboard`：概览与指标运维
- `users`：用户查询与身份管理

从分层上看，项目已具备比较完整的后端结构：

- API 层
- Service 层
- Repository 层
- SQLAlchemy 模型层
- Alembic 迁移
- 安全与权限中间层
- MCP / Tool 执行层

## 5. 典型使用场景

### 场景一：个人维护私有 Skills

用户上传自己的 Skill ZIP，平台保存版本和文件。之后用户在页面中启停 Skill、查看版本、生成 Token，让自己的本地 MCP 客户端按权限下载并执行。

### 场景二：团队复用公共 Skill 模板

团队先维护一批公共 Skill。普通用户进入 Public Skills 页面后，可以：

- 先加 reference，快速接入
- 再 clone，形成自己的可编辑副本

这样既能复用公共能力，又不会直接破坏源 Skill。

### 场景三：企业级受控分发

企业管理员开启 RBAC、审计、组织模型后，可以把平台作为内部 Skill Hub：

- 按企业 / 团队控制可见范围
- 给不同客户端发 Token
- 追踪谁下载了什么、执行了什么
- 统一管理版本与变更

## 6. 这个项目不主要做什么

结合当前代码，可以明确几个边界：

- 它不是一个在线托管执行任意代码的通用云函数平台
- 它不是一个开放公网的社区 Skill 市场
- 它不是只做前端展示的门户
- 它也不只是简单文件网盘

它的重点始终是：对 AI Agent 所需 Skills 做私有化、可治理、可分发、可审计的管理。

## 7. 一句话总结

Open SkillHub 当前可以理解为一个面向 AI Agent 生态的私有 SkillHub 平台，提供用户认证、Skill 上传与版本管理、公共 Skill 复用、Token 分发、权限治理、审计追踪，以及受控 MCP / Tool 执行能力，目标是把 Skills 从零散文件或仓库，提升为可管理、可复用、可分发的正式资产。
