# Desktop Responsive Review Workspace

> 状态：待审核产品规格

## 目标

将 desktop-client 重构为一个统一、响应式的审阅型工作区：四个一级页面共享左侧导航与全局状态语言，`Updates` 提供真正的多选批量分发体验，其他页面根据自身任务采用独立内容布局。

本规格延续 `2026-04-23-desktop-client-ui-redesign.md` 的 review-first 定位，不改变 Electron 权限边界、后端 API、单项分发服务、备份或写入校验语义。

## 用户问题

当前客户端采用顶部品牌栏和横向导航。随着 Home、Updates、Local Skills、Projects 四个一级页面及其操作增长，存在以下问题：

1. 宽屏空间没有形成稳定的导航、工作区和上下文层级。
2. Updates 仍以逐项卡片和逐项确认执行，处理多个安全变更时效率低。
3. 页面在中高 DPI 缩放下缺少针对性重排规则，固定三栏会压缩五列变更列表。
4. Home、Local Skills、Projects 共用视觉组件，但没有围绕各自主任务形成清晰的信息结构。

## 设计原则

- **统一 Shell，不统一页面任务**：导航、全局状态、断点和视觉 token 共用；右栏与底部操作按页面需要出现。
- **审阅优先**：轮询只刷新审阅状态，任何 Agent 目录写入仍需用户明确确认。
- **复用可靠写入路径**：批量体验由 Renderer 编排现有单项分发，不新增批量 IPC 或后端接口。
- **冲突默认安全**：冲突或目标检查失败的项目不默认选中，且不能只依赖颜色表达。
- **响应式重排而非缩小**：空间不足时摘要移动、列表转卡片、侧栏收窄，不压缩关键文字到不可读。

## 信息架构

### 共享 Desktop Shell

四个一级页面共享：

- 左侧品牌和导航：Home、Updates、Local Skills、Projects。
- 全局连接状态、主题切换和 Settings 入口。
- 一致的页面标题区、状态 Badge、卡片、按钮、错误和空状态语言。
- 相同的宽屏、中等宽度和窄屏断点策略。

Settings 继续使用抽屉，承载 API 配置、Agent 目标、Bridge 状态和最近活动。Settings 不新增为一级导航页面。

### Home

Home 继续回答“是否连接、是否需要关注、下一步去哪里”：

- 展示待审核数量、成功分发数量、已安装 Agent 数量和最近同步状态。
- 展示最多 3 个需要关注的更新。
- 提供进入 Updates 完整工作区的主入口。
- 不显示固定审批右栏，不显示批量分发底栏。
- Home 预览项不直接批量分发；分发操作集中在 Updates，减少两个页面之间的选择状态歧义。

### Updates

Updates 是唯一的完整审批工作区：

- 显示选择、状态、变更、目标 Agent 和远端版本等核心字段。
- 宽屏显示主列表与审批摘要右栏。
- 中等宽度将审批摘要重排为列表上方的横向摘要。
- 窄屏将表格行转为保持相同阅读顺序的变更卡片。
- 底部审批栏仅在至少选择一项时出现，且只覆盖内容区域。

### Local Skills

Local Skills 保持本地库存、上传、打开路径和删除职责：

- 主区域显示按名称分组后的 Skill 库存。
- 宽屏允许将选中 Skill 的路径、Agent 归属、版本和服务器状态展示在上下文详情区。
- 中窄屏将详情区变为抽屉或行内展开，不长期占用水平空间。
- 保留多路径选择和删除确认对话框语义。
- 不显示 Updates 的审批摘要或底部分发栏。

### Projects

Projects 保持项目记录、项目 Skill 扫描和显式导入职责：

- 宽屏使用项目列表与项目 Skill 详情的主从布局。
- 中窄屏保持“项目列表进入项目详情”的导航模式。
- 添加、重命名、移除项目以及导入 Skill 继续使用显式对话框。
- 不显示 Updates 的审批摘要或底部分发栏。

## 响应式规则

### 宽屏：`>= 1440px` CSS 宽度

- Shell 采用约 `216px` 左侧栏。
- Updates 使用弹性主区和约 `288px` 至 `304px` 审批摘要右栏。
- Local Skills 可显示上下文详情区。
- Projects 可显示项目列表与 Skill 详情主从布局。

### 中等宽度：`1100px` 至 `1439px`

- 保留左侧栏。
- Updates 右栏折叠为列表上方的摘要条。
- Local Skills 详情按需要进入抽屉或行内展开。
- Projects 可根据可用空间保持主从布局，空间不足时切换列表到详情导航。

### 窄屏：`< 1100px`

- 左侧栏收窄为带可访问名称的图标导航或可展开抽屉。
- Updates 表格转换为卡片，保留选择、状态、名称、目标和版本。
- Home 指标与预览按单列排列。
- Local Skills 和 Projects 使用单列列表及详情导航。
- 底部审批栏纵向重排，但仍不得遮挡最后一个可操作项目。

断点基于 Renderer 的 CSS 宽度，而不是物理像素。Electron 继续根据显示缩放换算当前目标窗口尺寸。

## 批量选择与分发

### 默认选择

- 默认选择所有需要实际写入、且最新预分发检查没有冲突的项目。
- 冲突、全局检查失败或目标状态未知的项目默认不选择。
- 已安装且只需同步本地记录的项目不进入批量文件分发选择。
- 选择仅存在于当前 Renderer 会话；刷新审阅状态后根据最新结果重新计算。

### 操作

- 用户可逐项选择或取消选择。
- “全选可分发项”仅选择当前检查结果允许分发的项目。
- “清除选择”取消所有选择。
- 第一版不提供“拒绝全部”，因为当前 pending update 不是可持久驳回的审批记录。

### 确认与执行

1. 用户点击“分发所选 N 项”。
2. 确认界面汇总 Skill 数量、实际写入目标、跳过目标和冲突项目。
3. 用户确认后，Renderer 按当前列表中的稳定顺序逐项调用现有单项分发能力。
4. 单项完成后立即更新对应行的执行状态和总体进度。
5. 单项失败不阻断后续项目。
6. 全部执行结束后刷新同步状态；失败项目继续留在待审核队列。

批量执行期间锁定选择、刷新和会导致离开 Updates 的导航操作。主按钮显示当前进度，例如“正在分发 2/4”。

### 完成结果

- 全部成功：显示成功数量并刷新为空或剩余 pending 状态。
- 部分成功：显示成功与失败数量，失败行保留原因和重试入口。
- 全部失败：保留所有失败项目和可操作错误说明。
- Activity 继续记录每个单项结果，批量完成可额外记录一次汇总事件。

## 可访问性要求

- 状态必须同时使用文字和视觉标记表达，不能只依赖颜色。
- 选择框、详情入口、主操作和更多操作均可通过键盘访问。
- 表格转卡片后保持一致的阅读顺序和焦点顺序。
- 批量进度使用可被辅助技术感知的状态区域，但不得为每个细小变化制造打断式通知。
- 图标导航必须具有可访问名称和清晰的当前页状态。
- 尊重 `prefers-reduced-motion`；必要状态变化不依赖位移动画。

## 错误处理

- 预分发检查失败时说明需要刷新检查、修复路径或检查连接。
- 分发失败保留单项错误，不折叠为无法定位的通用批量失败。
- 当 Renderer Bridge 不可用或配置未完成时，禁用分发并引导用户打开 Settings。
- 执行期间发生页面关闭或应用退出时，不声称未完成项目成功；已完成单项沿用现有持久状态，剩余项目在下次刷新后重新出现。

## 组件与状态边界

- `App.tsx` 保留顶层同步状态和分发入口。
- 批量选择、稳定执行顺序、进度与部分失败聚合应位于独立且可测试的 Renderer Hook 或控制器中。
- `UpdatesView` 负责 Updates 工作区组合，不承载文件写入逻辑。
- 变更表格/卡片、审批摘要和底部操作栏应为职责清晰的组件。
- Home、Local Skills 和 Projects 继续复用现有领域类型和回调，不改变其 IPC 合约。
- 所有新增用户文案进入 `en-US` 与 `zh-CN` 词典及其类型定义。

## 范围

本次包含：

- 统一四个一级页面的响应式左侧 Shell。
- Home 内容布局适配。
- Updates 多选批量分发及三种响应式布局。
- Local Skills 宽屏库存详情与窄屏重排。
- Projects 宽屏主从布局与窄屏列表/详情导航。
- 相关 Renderer 类型、组件、样式、i18n 和测试。
- 桌面设计、架构和任务跟踪文档更新。

## 非范围

- 后端 API 或数据库变更。
- 新增批量分发 IPC 合约。
- 改变单项分发、备份、验证或状态写回语义。
- 将 Settings 改成一级页面。
- 持久化用户的行选择。
- “拒绝全部”或远端审批拒绝状态。
- 改变 Agent 适配器、目标路径规则或项目 Skill 导入规则。

## 验收标准

1. 四个一级页面共享新的左侧 Shell，当前页、连接状态、主题和 Settings 入口清晰可用。
2. 在 `>= 1440px`、`1100px–1439px`、`< 1100px` 三类宽度下，四页均不存在关键操作遮挡或必须依赖页面级横向滚动的情况。
3. Home 显示核心状态与最多 3 个待审核预览，并引导进入 Updates。
4. Updates 默认选择所有安全且需要写入的项目，冲突项默认不选择并显示文字原因。
5. 用户可全选可分发项、清除选择，并通过一次确认顺序分发多个项目。
6. 单项失败不会阻断剩余项目，完成后可区分全部成功、部分成功和全部失败。
7. 批量执行复用现有单项分发能力，不新增后端或批量 IPC 合约。
8. Local Skills 保留上传、打开路径、多路径选择和删除确认能力，并在不同宽度下可用。
9. Projects 保留项目管理、扫描、打开目录和导入 Skill 能力，并在不同宽度下可用。
10. 所有新增文案具有中英文版本，状态和控件满足键盘与非纯颜色表达要求。
11. 定向测试、完整桌面测试、Electron 类型检查、生产构建、文档校验和 diff 检查通过。

cd desktop-client && npm run typecheck:electron
cd desktop-client && npm run build
python scripts/validate_agents_docs.py --level ERROR
