# 用户级运行时环境设计文档

> **平台限制**：本设计方案仅适用于 **Linux** 系统。文档中的代码示例、路径约定（如 venv 的 `bin/` 目录）、定时任务（cron）及安全扫描模式（`/etc/`、`/proc/` 等系统路径）均基于 Linux 环境编写，不支持 Windows 部署。

本文档描述了 Open SkillHub 的用户级运行时环境设计方案。由于 skill 的 scripts 脚本会在服务端运行，需要为每个用户的私有 skill 空间搭建独立的运行时环境。

## 核心架构：上传与部署分离

Skill 的生命周期分为**上传**和**部署**两个独立阶段：

```
上传 ZIP → 解析依赖声明（不安装）→ 立即返回 pending
用户点击「部署运行环境」→ 安装依赖 → 返回 ready
```

**设计优势**：
- 上传秒级响应，用户体验好
- 用户对每个 Skill 的运行环境状态有完全感知（红/黄/绿标识）
- 安装失败不阻塞上传，可以重试
- 多个 Skill 的安装互斥但各自独立触发
- 沙箱设计更简洁，安装和执行职责完全解耦

**Skill 运行环境状态模型**：

| 状态 | 含义 | 前端标识 | 可执行 |
|------|------|---------|--------|
| `pending` | 已上传，等待部署 | 🔴 红色 | 否 |
| `installing` | 依赖正在安装中 | 🟡 黄色 | 否 |
| `ready` | 运行环境就绪 | 🟢 绿色 | 是 |
| `failed` | 安装失败 | 🔴 红色 | 否 |

## 快速导航

### 核心概念

- **隔离模型**：用户级别隔离，每个用户拥有独立的 Python 虚拟环境
- **安全隔离**：subprocess + 环境清理 + 脚本扫描
- **并发安全**：用户级操作锁，防止部署过程中执行
- **部署模型**：上传与部署分离，用户手动触发运行环境部署

### 关键流程

1. [Skill 上传流程](./04-core-flows.md#1-skill-上传流程) - ZIP 验证、安全扫描、依赖解析（不安装）
2. [Skill 部署流程](./04-core-flows.md#2-skill-部署流程) - 依赖安装、冲突处理、状态更新（新增）
3. [Skill 执行流程](./04-core-flows.md#3-skill-执行流程) - 权限验证、环境状态检查、脚本执行
4. [Skill 删除流程](./04-core-flows.md#4-skill-删除流程) - 文件删除、依赖保留策略
5. [版本回滚流程](./04-core-flows.md#7-skill-版本回滚流程) - 代码回滚、依赖保持

### 设计决策速查

| 决策项 | 选择 |
|--------|------|
| 隔离模型 | 用户级别隔离 |
| 安全隔离层级 | subprocess + 环境清理 + 脚本扫描 |
| 环境创建时机 | 首次部署 skill 时 |
| 依赖安装时机 | 用户手动触发部署后安装 |
| 依赖冲突策略 | 部署阶段前端交互式处理 |
| 并发安全 | 用户级操作锁 |
| 部署模型 | 上传与部署分离，支持异步部署 |

详细决策理由请参考 [概述 - 核心决策](./01-overview.md#核心决策)。
