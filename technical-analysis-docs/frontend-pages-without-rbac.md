# 无 RBAC 模式下的前端页面说明

> 本文从前端页面出发，说明无 `RBAC` 模式下用户在控制台里会看到什么、能做什么、哪些页面即使存在也不属于主要使用路径。

---

如果你想解决的是下面这类问题，这篇文档最有用：

- “我应该去哪个页面做这件事？”

- “为什么我能看到某个页面，但某些操作不能做？”
- “无 RBAC 时，前端到底呈现哪些能力？”

## 页面总览

在无 `RBAC` 模式下，对普通用户最重要的页面通常是下面几类：

| 页面 | 路径 | 主要用途 | 是否是主路径 |
|------|------|----------|--------------|
| 登录 | `/login` | 登录系统 | 是 |
| 注册 | `/register` | 注册账号 | 视配置而定 |
| 仪表盘 | `/dashboard` | 查看概览和快捷入口 | 是 |
| Skills | `/skills` | 管理自己的 Skill | 是 |
| 新建 Skill | `/skills/new` | 创建新的 Skill | 是 |
| Skill 详情 | `/skills/{skillUuid}` | 查看和维护某个 Skill | 是 |
| Public Skills | `/public-skills` | 浏览公共 Skill、创建 reference 或 clone | 是 |
| Tokens | `/tokens` | 创建和管理 API Token | 是 |
| 个人信息 | `/profile` | 维护个人资料 | 是 |
| 安全 | `/security` | 退出登录等安全操作 | 是 |
| 审计日志 | `/audit` | 查看审计日志 | 不是主路径 |
| 用户管理 | `/admin/users` | 管理用户 | 不是主路径 |

## 主路径页面怎么理解

### 1. `/dashboard`

这是用户进入系统后的总览页。

它的作用更像一个“导航枢纽”，而不是主要工作页。  
通常你会在这里确认：

- 当前账号是否正常
- 当前有多少可用 Skill
- 当前有多少 Token
- 快捷入口是否可用

如果你是第一次使用，最常见的下一步是：

- 去 `/skills`
- 去 `/public-skills`
- 去 `/tokens`

### 2. `/skills`

这是无 `RBAC` 模式下最重要的页面之一。  
它负责展示和管理“你自己的 Skill 列表”。

你在这里通常会做的事：

- 查看自己名下的 Skill
- 搜索 Skill
- 查看启用 / 停用状态
- 打开详情页
- 停用或重新启用普通 Skill
- 删除自己名下的 Skill

这页最重要的认知是：

**这里不是系统全局 Skill 列表，而是以“你自己的 Skill”为中心的工作区。**

如果你在这里看到 `reference` 或 `clone`，那是因为它们已经属于你的使用视角了。

### 3. `/skills/new`

这是新建 Skill 的入口页。

适合两类情况：

- 你想先创建一条 Skill 记录，再逐步上传内容
- 你准备从零开始维护自己的私有 Skill

如果你已经知道自己只是想“拿一个公共 Skill 变成自己的”，那通常不必先来这里，而是先去 `/public-skills`。

### 4. `/skills/{skillUuid}`

这是单个 Skill 的详情和维护页面。

你在这里通常会关心：

- 当前 Skill 的名称、描述、状态
- 类型是 `private`、`reference` 还是 `clone`
- 当前解析到的版本
- 是否允许修改

这页很适合理解一个 Skill 的真实状态。  
尤其当你不确定“这到底是独立副本还是引用”时，这一页最有帮助。

### 5. `/public-skills`

这是系统公共 Skill 库的浏览页。

你在这里通常会做的事：

- 搜索公共 Skill
- 查看系统预置的 Skill
- 将某个公共 Skill 添加为 `reference`
- 将某个公共 Skill 复制为自己的 `clone`
- 尝试下载

这页最重要的认知是：

**它是“公共能力入口”，不是“公共编辑空间”。**

用户在这里主要做的是“拿来用”或“拿来变成自己的”，而不是直接维护公共 Skill 本体。

### 6. `/tokens`

这是把“网页里的 Skill 管理”转变成“客户端可调用 Skill”的关键页面。

你在这里通常会做的事：

- 创建 API Token
- 查看已有 Token
- 删除不再使用的 Token

如果你的目标是“让自己的 MCP 客户端或其他工具访问系统里的 Skill”，这个页面几乎一定会用到。

### 7. `/profile`

这是个人资料页。

它解决的是账号信息问题，而不是 Skill 问题。  
常见用途包括：

- 查看自己的账号信息
- 更新个人资料

### 8. `/security`

这是安全相关页面。

在普通用户视角下，它通常用于：

- 处理安全相关设置
- 执行退出登录等动作

## 非主路径页面怎么理解

### 1. `/audit`

这个页面是否出现，取决于前端功能开关和后端能力是否开启。

即使页面存在，它也不属于无 `RBAC` 模式下普通用户的核心工作路径。  
对大多数个人用户来说，它不是开始使用系统所必需的页面。

如果你的目标只是“管理自己的 Skill 并让自己的客户端调用”，通常不需要先理解这个页面。

### 2. `/admin/users`

这个页面名字就说明了它是“管理用户”的页面。

在无 `RBAC` 模式下，它不是普通用户使用路径的一部分。  
即使路由存在，也不意味着普通用户应该或能够使用它。

对无 `RBAC` 模式的普通使用者来说，可以把它视为：

- 不属于自己的日常页面
- 不是核心流程的一部分

---

## 推荐的页面使用顺序

对于大多数用户，推荐按下面的顺序理解和使用页面：

1. `/dashboard`
2. `/public-skills`
3. `/skills`
4. `/skills/{skillUuid}`
5. `/tokens`
6. `/profile`
7. `/security`

如果你已经有现成 Skill，要改成：

1. `/dashboard`
2. `/skills/new`
3. `/skills`
4. `/skills/{skillUuid}`
5. `/tokens`

---

## 两条最容易混淆的页面边界

### `Skills` 和 `Public Skills` 的区别

最简单的区分方法：

- `Skills` 是“我自己的工作区”
- `Public Skills` 是“系统给我的公共能力入口”

如果你想管理自己名下的东西，去 `Skills`。  
如果你想先从系统现成能力里挑一个，去 `Public Skills`。

### `Tokens` 和 `Skills` 的区别

最简单的区分方法：

- `Skills` 负责管理能力本身
- `Tokens` 负责让客户端能安全访问这些能力

如果你没有 Token，很多客户端接入场景就走不通。  
如果你只有 Token 没有 Skill，也没有实际可用能力。

## 给产品和文档写作者的建议

如果你需要在面向用户的说明里介绍前端页面，建议优先使用下面这种描述方式：

- 先按页面分组
- 每个页面只回答三个问题：
  - 这是干什么的
  - 用户在这里通常做什么
  - 这是不是主路径

这样会比直接罗列接口、开关和权限更适合普通使用者阅读。
