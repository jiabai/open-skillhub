## 1. 概述

### 1.1 项目目标

构建企业级私有云技能服务，使 OpenClaw AI 助手能够安全地访问和执行企业私有技能，无需本地安装，同时满足企业数据安全、权限管控、审计合规要求。

### 1.2 核心价值

| 受益方 | 价值 |
|--------|------|
| **企业** | 技能资产沉淀、统一管控、安全合规 |
| **员工** | 无需手动安装、技能自动同步、开箱即用 |
| **AI 助手** | 按需获取技能、动态扩展能力、统一接口 |

### 1.3 适用范围

- **部署场景：** 企业内网/私有云/VPC 专有云
- **目标客户：** 金融、国企、政府、大型企业
- **技能类型：** 企业内部技能（不公开、不发布到 GitHub）

## 2. 需求背景

### 2.1 当前痛点

| 痛点 | 描述 | 影响 |
|------|------|------|
| **技能分散** | 技能散落在员工本地，难以统一管理 | 离职员工技能丢失 |
| **版本混乱** | 不同员工使用不同版本 | 协作困难、结果不一致 |
| **安全风险** | 敏感技能可能泄露 | 企业数据安全风险 |
| **无法审计** | 技能使用情况无法追踪 | 合规审计困难 |
| **安装繁琐** | 每个员工需手动安装 | 效率低下、体验差 |

### 2.2 需求来源

- **需求方：** 企业内部（金融/国企客户）
- **触发场景：** 企业希望 AI 助手使用内部技能，但技能不能公开
- **核心诉求：** 安全、私有、可审计、易用

**实现方案（与当前代码对齐）**

- 上传接口扩展为 ZIP 上传与单文件上传兼容，ZIP 解包后进行文件名与路径校验
- ZIP 内解析 `SKILL.md` 的 frontmatter，提取 name/description/version/dependencies
- 版本目录采用 `_versions/{version}` 存档，当前版本覆盖到技能根目录
- 版本列表与回滚通过新增 API 完成，回滚时复制目标版本到根目录
- 下架通过 `is_active` 字段控制，列表默认仅返回已启用技能
- 依赖安装策略采用“客户端安装”：服务端只输出依赖清单与安装指引，不在服务端执行安装
- 版本差异对比提供 API，输出文件新增/删除/修改列表，并对小文本文件返回 unified diff
- 下架缓存失效通过 `cache_revoked_at` 时间戳实现，客户端缓存命中时需校验失效点

**实现细节（接口与数据约定）**

1) **Skill 文件结构与版本归档**

- Skill 当前版本目录：`{SKILL_STORAGE_PATH}/{user_id}/{skill_name}/`
- Skill 历史版本归档：`{SKILL_STORAGE_PATH}/{user_id}/{skill_name}/_versions/{version}/`
- 服务端行为：每次 ZIP 上传会先写入 `_versions/{version}`，然后覆盖复制到“当前版本目录”

2) **metadata 来源与约定**

- ZIP 包必须包含 `SKILL.md`
- `SKILL.md` frontmatter 支持字段：`name`、`description`、`version`、`dependencies`
- `dependencies` 推荐用数组：`dependencies: [requests, pydantic]`

3) **版本与标识规则**

- `skill_id` 为数据库 UUID（全局唯一且不可变）
- `name` 为可读稳定标识（推荐小写字母、数字与短横线）
- `version` 采用 SemVer（如 `1.2.0`），不允许回退式发布
- 回滚仅影响当前版本指针，不删除历史版本

4) **技能上传**

- `POST /api/v1/skills/upload`
  - 表单：`skill_uuid`（必填）、`file`（必填）、`metadata`（可选，JSON 字符串）
  - `.zip`：触发版本创建与解析；非 `.zip`：按单文件上传处理
  - 成功（zip）：返回 `version`、`current_version`、`dependencies`

5) **版本列表与回滚**

- `GET /api/v1/skills/{skill_uuid}/versions`
- `POST /api/v1/skills/{skill_uuid}/versions/{version}/rollback`
  - 回滚后：当前版本目录会被目标版本文件覆盖
  - Skill 元数据：`current_version` 更新为回滚目标版本

6) **下架与缓存失效（客户端安装/本地缓存模式）**

- `POST /api/v1/skills/{skill_uuid}/deactivate`
  - `is_active=false`
  - `cache_revoked_at=当前时间`
- `POST /api/v1/skills/{skill_uuid}/activate`
  - `is_active=true`
- 客户端缓存校验建议：
  - 缓存条目保存 `cached_at`
  - 当服务端 `cache_revoked_at != null` 且 `cached_at <= cache_revoked_at` 时视为失效，需重新拉取

7) **依赖安装策略（C：客户端安装）**

- 服务端只提供依赖清单与安装指引，不执行安装
- `GET /api/v1/skills/{skill_uuid}/versions/{version}/install-instructions`
  - 返回 `strategy=client`、`dependencies`、`requirements_text`、`commands`

8) **版本差异对比**

- `GET /api/v1/skills/{skill_uuid}/versions/diff?from={from_version}&to={to_version}`
  - 返回 `added` / `removed` / `modified`
  - `modified[].diff` 对小文本文件返回 unified diff；大文件或二进制文件可返回空 diff

#### 4.2.2 权限管理（P0）

| 功能 ID | 功能名称 | 描述 | 优先级 |
|---------|----------|------|--------|
| F-011 | 企业认证 | LDAP/AD 集成，SSO 单点登录 | P0 |
| F-012 | RBAC 权限 | 角色-based 访问控制 | P0 |
| F-013 | 可见性控制 | 企业/团队/个人三级可见性 | P0 |

**权限与可见性定义**

- **企业级可见**：同一企业租户内全员可见
- **团队级可见**：同一团队成员可见，团队成员来源于企业目录或组织结构
- **个人级可见**：仅创建者本人可见
- **继承规则**：企业 > 团队 > 个人，权限不提升但可收窄
- **默认策略**：新上传技能默认个人级（private）可见，敏感技能可按需配置团队级/企业级

## 6. 安全要求

### 6.1 安全架构


#### 6.3.2 审计要求

| 要求 | 实现方案 |
|------|----------|
| **完整性** | 所有操作记录，不可遗漏 |
| **不可篡改** | 日志写入后不可修改（WORM 存储） |
| **可追溯** | 支持按用户/时间/操作查询 |
| **保留期** | 最少 3 年，支持 7 年（金融合规） |
| **可导出** | 支持 CSV/JSON 格式导出 |

### 6.4 密钥管理与轮换

| 要求 | 实现方案 |
|------|----------|
| **密钥托管** | 统一 KMS 或 HSM 托管，禁止明文落盘 |
| **定期轮换** | 业务密钥最少每 90 天轮换 |
| **权限隔离** | 密钥管理与运维权限隔离 |
| **审计记录** | 密钥访问与轮换记录写入审计日志 |

### 6.5 数据分级与合规

| 要求 | 实现方案 |
|------|----------|
| **数据分级** | 对输入/输出/日志按机密级别标识与访问控制 |
| **脱敏策略** | 关键字段脱敏或哈希化，审计日志保留最小必要字段 |
| **数据驻留** | 支持企业内网与指定地域存储 |
| **合规要求** | 满足金融、政府与国企相关合规审计要求 |

### 7.3 认证与鉴权约定

| 项目 | 约定 |
|------|------|
| **Token 生命周期** | 访问 Token 默认 30 分钟，支持刷新 Token |

| **权限映射** | LDAP/AD 组映射到系统角色与 Scope |

| **异常响应** | 401 未认证、403 无权限、429 触发限流 |
